- Delayed native storage read/write or a stale GPS/search/center callback after a manual choice must never replace the newer choice (Tasks 1, 3, 4).

- Legacy directory/detail/login flows and rejected dirty-form closes must preserve city, category, query, selection, scroll and pan while the new surfaces remain mutually exclusive (Tasks 5–7).

Storage key `eventopia.discovery.v1`, native timeout 1500ms, queued writes, local mirror and updatedAt selection prevent late older native data winning. Failed persistence is nonblocking.
- `frontend/src/discovery/geoNames.ts`: bounded public provider transport/parsing and parent comparison; no API-client auth. `searchCityPlaces(query: string, cities: CityOption[], signal?: AbortSignal): Promise<CityPlace[]>`; `resolvePlaceCenter(geo: GeoSelection, signal?: AbortSignal): Promise<PlaceSelection | null>`. - `frontend/src/discovery/resolveCity.ts`: `resolveCurrentCity(position: DevicePosition, cities: CityOption[], signal?: AbortSignal): Promise<CityPlace | null>`. Retain old `resolveCity(...): Promise<CityOption | null>` as a narrow compatibility wrapper until old detector is removed; no duplicate algorithms.
- `frontend/src/discovery/deviceLocation.ts`: keep requestDeviceLocation; add `getLocationPermission(signal?: AbortSignal): Promise<'granted' | 'prompt' | 'denied' | 'unavailable' | 'unknown'>`. Permission inspection never asks for location.
- `frontend/src/discovery/useDiscoveryLocation.ts`: one async owner, consumes current DiscoveryState, catalogue, route eligibility, active surface and URL update callback. Context exposes its `location` object with `place`, effective `mode`, `ready`, `welcome`, `status` (`idle|locating|resolving|denied|unavailable|unmatched|error`), `notice: string|null`, `persistenceWarning: boolean`, `recent`, `cameraRequest: { sequence: number; place: PlaceSelection|null }`, plus `selectPlace(place)`, `useCurrentLocation()`, `recenter()`, `forgetPlaces()`, `dismissWelcome()`, `searchPlaces(query): Promise<CityPlace[]>`, `cancelPending()`. Actions may return void/promises as needed but consumers do not mutate owner state. `cameraRequest` initial sequence zero means no movement; explicit forget may request neutral reset. Public fields/actions are the stable cross-task boundary.
- `DiscoveryContext.tsx` additionally exposes `surface: 'none'|'city'|'search'|'results'|'profile'|'create'`, `openSurface(surface, returnTo?: 'none'|'profile')`, `closeSurface()`, and a stable `cameraMemory` ref containing `{ center:[number,number]; zoom:number; bearing:number; pitch:number; appliedSequence:number } | null`. Surface transitions cancel old async work; close city from Profile returns Profile. Create refuses/defers external dismissal through the existing dirty-form flow.
- `DiscoveryState` adds optional `follow?: true`; absent means unmarked/manual visit. `parseDiscovery`/`serializeDiscovery` preserve it without changing legacy object shape when absent.
- `Map/RenderMap.tsx` consumes context cameraRequest/cameraMemory; provider resolves centers outside map renderer. Existing style recovery/marker cleanup remains.
- `components/Discovery/CityPicker.tsx` is presentation/search debounce only; it uses location owner, never starts its own device/provider lifecycle.
- `components/Discovery/DiscoveryProfile.tsx` reuses factored account contents and adds device place settings. `DiscoverySurface.tsx` provides shared covering surfaces using existing Radix/Vaul, focus/Back behavior; creation keeps its existing drawer.
- `index.css` and viewport hook own shared overlay geometry CSS variables (dock/credits/preview/safe areas), no unrelated global redesign.
