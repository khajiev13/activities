> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the approved phone-first Eventopia experience: map-led city discovery, persistent bottom navigation, usable forms, and optional device-location city selection.

**Architecture:** Reuse React Router, the authenticated API client, Radix/Vaul primitives and MapTiler layers. A small discovery model and provider own coarse geographic/search context and result loading; pages consume that state rather than each fetching their own geography. Keep native Telegram UI capabilities and read-only device-location resolution separate from authentication and location creation.

## Global Constraints

- “Four labeled destinations: Explore, Activities, Teams, Organizations. Create remains a contextual action. Desktop gets a rail and a results panel.”
- “Use 44–48px app controls, readable labels, visible focus and measured contrast.” Use 16px inputs and readable 12px-or-larger secondary copy; main card titles/body 16px.
- “Changing views preserves the city, entity and text search. Returning from a detail or login restores that context and the list position.”
- “Moving the map changes the view only; results remain city-scoped.” Preserve explicit country/state browsing as an alternative.
- “A first visit offers ‘Use my location’ and manual city search. It does not assume Beijing is the visitor’s city.”
- “Auto-select only a unique match with compatible country and state, then query using the exact stored names.” Manual selection wins over pending GPS callbacks.
- “Do not store exact coordinates in application storage, URLs, account records or logs.” A provider necessarily receives lookup coordinates; disclose this by the action. No continuous tracking or automatic permission prompt.
- “The lookup provider necessarily receives the requested coordinates”; use unauthenticated fetch with credentials omitted, never Eventopia's authenticated Axios client for the provider.
- “Preserve all existing activity, competition, team, organization and image fields.” Retain backend business rules and payload contracts.
- “An explicit user theme wins, then Telegram’s theme inside Telegram, then the browser’s system preference.”
- “No new chat, payments, saved activities, profile editor, background location tracking, radius search or framework migration.”
- Keep existing list/detail/login/register URLs and Mini App authentication behavior. No tokens, phone values, OTP codes, refresh tokens, `init_data`, private config or credentials in output, screenshots, commits or logs.

## Review Focus

1. Delayed location/API responses after manual city choice, navigation or unmount must never overwrite newer context: Tasks 1, 3, 4 test deferred responses and cancellation.
2. Same city name in different countries/states, district reverse-geocodes and country-only nodes must not select the wrong place: Tasks 1 and 3 test full tuples and unmatched/ambiguous states.
3. A request failure or invalid competition must leave creation drafts editable and retryable, with no duplicate writes: Tasks 6 and 7 test validation, rejected requests and double clicks.
4. Detail → login → detail/back must preserve intent/search while logout and native Telegram sign-in stay correct: Tasks 4, 5 and 8 exercise the actual routing/state behavior.
5. Short viewports, large text, the keyboard, map failure and Telegram safe areas must retain a usable alternative and visible actions: Tasks 2, 4 and 8 exercise responsive/viewport behavior; final real-phone check is explicit.
